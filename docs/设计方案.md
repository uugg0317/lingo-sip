# 语滴 Lingo Sip · 设计方案

> 本文件记录初始设计与技术取舍。当前安装方式和功能以 [README](../README.md) 与源码为准。

> 一个只在"任务与任务之间的缝隙"里出现的英语学习扩展。
> 目标不是让你每天多学一小时，而是让你**本来会浪费掉的几十个 20 秒**变成复习量。

---

## 一、需求拆解

### 1.1 场景与三条硬约束

| 约束 | 具体含义 | 对应的设计动作 |
| --- | --- | --- |
| 不打断主任务 | 出现时用户必须能"看一眼就走"，代价接近 0 | 单张卡 10~30 秒可完成；鼠标一停就暂停计时；不做弹窗、不做遮罩、不做声音（默认） |
| 不额外占用整块时间 | 只有碎片，没有"学习时段" | 不设课程、不设每日必修、学不完没有惩罚；随时中断不丢进度 |
| 零学习成本 | 装上就能用，不需要读说明书 | 默认值即可用；只有两个动作按钮；所有参数有合理默认，改不改都能跑 |

### 1.2 可介入时机的识别

把"用户可能正好有空"的瞬间穷举出来，逐个评估打扰风险：

| # | 时机 | 为什么是空隙 | 打扰风险 | 默认 |
| --- | --- | --- | --- | --- |
| T1 | **切换标签页之后** | 一个任务收尾、另一个还没开始的天然断点 | 低（用户自己按的切换） | ✅ 开 |
| T2 | **页面加载完成** | 等待结束的瞬间，注意力本来就悬空 | 低 | ✅ 开 |
| T3 | **页面内停顿** | 鼠标键盘滚动都停下 ≥30 秒 = 在读、在想、在等人 | 中（可能在精读长文） | ✅ 开，阈值可调 |
| T4 | **定时兜底** | 连续忙碌、一直没出现自然空隙时的兜底 | 中 | ✅ 开，45 分钟 |
| T5 | **离开电脑后回来** | 回到桌前，正准备重新进入状态 | 中高（回来通常有正事） | ⛔ 关 |
| T6 | **手动请求** | 用户主动点"立即学一张" | 无（用户意图明确） | 始终可用 |

### 1.3 双层触发模型

把一个"能不能弹"的问题拆成两层，**两层都通过才出现**：

```
第一层 时机层（什么时候"可能"弹）
   T1 切换标签 ── 延迟 1.2s ─┐
   T2 加载完成 ── 延迟 1.5s ─┤
   T3 页面停顿 ≥30s ────────┼──► 第二层
   T4 距上次 ≥45min ────────┤
   T5 回到电脑 ── 延迟 2s ──┘
   （延迟的意义：躲开页面自己刚加载完时的弹窗、跳转、自动聚焦）

第二层 闸门层（真的能弹吗）—— 全部通过才算数
   ① 总开关 on
   ② 不在暂停期（用户手动暂停 15min / 1h / 4h / 今天）
   ③ 不在安静时段（默认关闭，可设 22:00-08:00）
   ④ 全局冷却：距上次展示 ≥ 4 分钟
   ⑤ 本小时 < 5 张
   ⑥ 今天 < 30 张
   ⑦ 当前标签页 5 分钟内没出现过
   ⑧ 不在免打扰名单（域名 / URL 通配）
   ⑨ 只在"当前活动且窗口聚焦"的标签页
   ⑩ 页面侧否决：正在输入 / 有选中文字 / 播放音视频 / 全屏 / 不可见
```

**关键设计：时机层只负责"申请"，闸门层才负责"批准"，而批准权唯一集中在 service worker。**
内容脚本永远不做调度决策，它只回答"我这里现在方不方便"。这样十个标签页不会各弹各的。

### 1.4 绝对不打扰清单（页面侧硬否决）

- 焦点在 `input` / `textarea` / `select` / `contenteditable` 上 → 用户正在打字
- 有非折叠的文本选区 → 用户可能正要复制、翻译、搜索
- 页面有正在播放且未静音的 `<video>` / `<audio>` → 在看剧/开会/听歌
- 处于全屏 → 演示、看视频
- 标签页不可见 / 窗口未聚焦 → 用户在别的窗口忙
- 已经有一张卡在页面上 → 一次只给一张
- 非 `http(s)` 页面、非顶层文档 → 不注入、不弹

### 1.5 频率上限的取值依据

| 参数 | 默认 | 依据 |
| --- | --- | --- |
| 全局冷却 | 4 分钟 | 用户主观"烦"的阈值大致在 5 分钟以内 |
| 每小时上限 | 5 张 | 一个工作小时里，5 次 20 秒 = 100 秒，占比 <5% |
| 每天上限 | 30 张 | 约 10 分钟总时长，属于"顺手"而非"任务" |
| 单页冷却 | 5 分钟 | 防止在同一页面反复被打扰 |
| 新词/天 | 20 个 | 超过这个量，复习队列会在几天后雪崩 |

### 2.2 间隔重复调度

**模型：7 档莱特纳盒子 + 间隔表。** 刻意不用完整 SM-2 —— 参数少、行为可预期，用户不需要理解算法。

| 盒子 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 下次间隔 | 10min | 45min | 12h | 1d | 3d | 7d | 21d |
| "稍后复习"推迟 | 10min | 30min | 3h | 12h | 1d | 3d | 7d |

```
状态机：

  新词 ──首次展示──► learning(box 0)
                        │
        ┌───────────────┼────────────────┐
        │ 已掌握        │ 稍后复习        │ 超时/跳过
        ▼               ▼                ▼
   box + 1         box - 1          box 不变
   box≥5 → mastered  due = +snooze    due = +20min
```

- **点"已掌握"** → `box + 1`，`due = now + interval(box)`；`box ≥ 5` 标记为 `mastered`，退出自动队列。
- **点"稍后复习"** → `box - 1`，`due = now + snooze(box)`。语义是"我还没记住"，所以盒子退一格。
- **超时淡出 / 主动跳过** → 盒子不变，`due = now + 20min`。**不视为遗忘**，用户不会因为"刚才在忙"而被惩罚。
- **已掌握的词** 超过 14 天没见会回来一次（保温复习），可在设置里关闭。

**取词优先级**（`srs.pickNext`）：

```
① 到期复习     progress.due ≤ now 且非 mastered，按 due 升序（先还债）
② 新词         只在前 40 个未见过的词里做"越靠前越容易被选中"的加权随机
③ 保温         mastered 且 lastSeen > 14 天
④ 兜底         最久没见到的在学词
```

新词配额用完时（默认 20/天）自动跳过 ②，只做复习 —— **宁可少学新词，也不攒复习债**。

### 2.3 数据结构

全部数据存在单个 storage 键 `lingoSip` 下，便于整体备份与原子写入：

```js
{
  version: 1,
  settings: { /* 见 constants.js DEFAULT_SETTINGS，约 25 个字段 */ },
  progress: {
    "w001": { box: 2, due: 1735689600000, status: "learning",
              reps: 3, known: 2, snooze: 1, seen: 4, lastSeen: 1735680000000 }
  },
  stats: { "2026-02-14": { shown: 12, known: 9, snooze: 2, seconds: 210 } },
  runtime: {
    lastShownAt, lastWordId, hourKey, hourCount, dayKey, dayCount, newCount,
    tabShown: { "1234": 1735680000000 },   // 单页冷却
    lastBlockReason: "冷却中，132 秒后可出现 · 切换标签时",
    log: [ { ts, text } ]                   // 最近 60 条事件
  },
  customWords: [ /* 用户自己的词条 */ ]
}
```

`progress` 按**单词 id** 关联而不是行号，所以：重复导入不丢进度、调整词表顺序不影响学习记录、内置词表升级不会清空历史。

## 三、交互设计

### 3.1 三种呈现形态

| 形态 | 位置 | 承载内容 | 打扰度 |
| --- | --- | --- | --- |
| **卡片浮层** | 网页右下角，342px，Shadow DOM 隔离 | 一次学习（主战场） | 最低：不遮正文、不抢焦点、无遮罩 |
| **弹窗** | 点扩展图标 | 今日进度、暂停、立即学一张 | 用户主动 |
| **角标** | 工具栏图标右下 | 待学数量（或 ✓） | 无感 |
| **连学窗** | 独立小窗口 420×460 | 主动连学多张 | 用户主动 |

卡片**不抢焦点、不需要关闭、不阻塞页面**：它在最右下角滑出，你不理它，25 秒后它自己走。

### 3.2 单次学习时序（目标 ≤30 秒）

```
0.0s   卡片从右下角滑入（180ms），顶部进度条开始走
       单词 + 音标 + 词性   ← 2~3 秒：认一下
       （回忆模式：释义模糊，想好点"看释义"）
       ┌─ 想听发音 ─── 点 🔊 / 空格        +1 秒
2.0s   释义 + 例句（中英对照）← 3~8 秒：理解 + 记语境
       ┌─ 鼠标移到卡片上 → 倒计时暂停（想看多久看多久）
10s    判断：记住 / 没记住
       ┌─ 记住 ─── 1 或点"已掌握"          0.5 秒
       └─ 没记住 ─ 2 或点"稍后复习"         0.5 秒
25s   没操作 → 淡出，不记账、不扣分，20 分钟后再见
```

**"零操作也能结束"** 是这条流程的核心：不点任何一个按钮，学习也不会卡在那里。

### 3.3 一键跳过与暂停

| 动作 | 入口 | 效果 |
| --- | --- | --- |
| 跳过这一张 | `Esc` / 右上角 ✕ | 卡片立即消失，20 分钟后再见 |
| 暂停 1 小时 | 卡片右上角 ⏸ | 立即暂停并关掉卡片，弹窗里可恢复 |
| 暂停 15min/1h/4h/今天 | 弹窗 | — |
| 恢复 | 弹窗（暂停时显示为"已暂停至 hh:mm · 恢复"） | — |
| 总关闭 | 弹窗开关 / 设置页 | 只影响自动出现，手动学习仍可用 |

### 3.4 键盘映射（仅在卡片可见时生效，且不抢输入焦点）

| 键 | 动作 |
| --- | --- |
| `1` | 已掌握 |
| `2` | 稍后复习 |
| `空格` | 朗读 |
| `3` | 看释义（回忆模式） |
| `Esc` | 跳过 |
| `Alt+Shift+E` | 全局：立刻来一张（可在 `chrome://extensions/shortcuts` 改） |

按键监听只在卡片存在时挂载，且**焦点在输入框时直接放行不拦截**。

### 3.5 视觉与无障碍

- **Shadow DOM + `:host { all: initial }`**：网站样式改不到卡片，卡片也不会污染网站。
- **构造式样式表**（`adoptedStyleSheets`）：绕过 GitHub / Google / 网银这类站点的严格 CSP，否则卡片会变成裸文字。
- 浅色 / 深色自动适配（`prefers-color-scheme`）。
- 尊重 `prefers-reduced-motion`：关闭入场动画。
- 文字对比度 ≥ 4.5:1；全部交互元素有 `title` 与 `aria-label`。
- 点击区域 ≥ 24×24px。

## 四、技术实现

### 4.1 目录结构

```
lingo-sip/
├── manifest.json              MV3 配置
├── package.json               零依赖，仅供 node 自检
├── README.md
├── docs/设计方案.md
├── assets/icons/              icon16/32/48/128.png（脚本生成）
├── src/
│   ├── background/service-worker.js   ★ 唯一决策点
│   ├── core/                          纯逻辑，四个界面共用
│   │   ├── constants.js  store.js  srs.js  stats.js
│   │   ├── scheduler.js  wordbank.js  view.js  tts.js
│   ├── content/bootstrap.js           经典脚本引导（动态 import）
│   ├── content/app.js                 页面侧
│   ├── ui/card.js                     卡片组件（Shadow DOM）
│   ├── data/words.js                  内置词表（纯数据）
│   ├── popup/  options/  pages/
└── tools/validate.js  tools/make-icons.mjs
```

### 4.2 manifest 关键配置

```json
{
  "manifest_version": 3,
  "background": { "service_worker": "src/background/service-worker.js", "type": "module" },
  "permissions": ["storage", "alarms", "idle", "tabs", "tts"],
  "content_scripts": [{
    "matches": ["http://*/*", "https://*/*"],
    "js": ["src/content/bootstrap.js"],
    "run_at": "document_idle",
    "all_frames": false
  }],
  "web_accessible_resources": [{
    "resources": ["src/content/*.js", "src/core/*.js", "src/ui/*.js", "src/data/*.js"],
    "matches": ["http://*/*", "https://*/*"]
  }]
}
```

**没有 `host_permissions`，没有 `scripting`，没有 `webRequest`，没有 `notifications`。**
`web_accessible_resources` 是必需的：内容脚本要动态 `import()` 那些模块。

### 4.3 关键工程决策

| 问题 | 决策 | 理由 |
| --- | --- | --- |
| MV3 service worker 随时被回收 | **不保存任何必须活下来的内存状态**，所有计数读写 `chrome.storage` | 浏览器 30 秒无事件就杀 SW，任何内存变量都不可信 |
| storage 读改写非原子 | `store.js` 里用 **Promise 串行队列** 把所有写操作排队 | 并发的"展示"和"作答"不会互相覆盖 |
| 定时器在 SW 里不可靠 | 只保留一个 `chrome.alarms` 每分钟 tick | MV3 禁止 `setInterval` 长驻 |
| 内容脚本不能用 ESM 声明 | `content_scripts` 只放一个 10 行的 `bootstrap.js`，它动态 `import()` 真正的模块 | 让内容脚本与 SW/popup/options **共用同一份 core 代码**，不复制粘贴 |
| 严 CSP 站点拦截 `<style>` | `new CSSStyleSheet()` + `adoptedStyleSheets`，老浏览器才回退 `<style>` | GitHub / Google / 网银会拒绝内容脚本插入的 style 元素 |
| 页面可能注入恶意内容 | 卡片全部用 `textContent` 渲染，不用 `innerHTML` | 自定义词条里的 HTML 不会被执行 |
| 发音被浏览器自动播放策略拦 | 发音统一走后台 `chrome.tts`（不受页面策略限制），失败回退 `speechSynthesis` | 一次点击即可出声 |
| 多标签页争抢 | 决策与记账只在 SW；内容脚本只回答"方不方便" | 不会出现两个标签页同时弹卡 |
| 用户想弄清楚"为什么没弹" | SW 每次拦截都写 `runtime.lastBlockReason` + 事件日志 | 设置页"诊断"直接给出中文原因，省掉猜 |

### 4.4 消息协议

| 消息 | 方向 | 用途 |
| --- | --- | --- |
| `card:request` | 页面/学习窗 → SW | "我这里有空，来一张"（含 trigger） |
| `card:show` | SW → 页面 | 下发卡片数据 |
| `card:shown` | 页面 → SW | 确认已渲染，**此刻才消耗配额** |
| `card:action` | 页面 → SW | 已掌握 / 稍后复习 |
| `card:dismissed` | 页面 → SW | 超时 / 关闭 |
| `app:pause` / `app:resume` | 任意 → SW | 暂停与恢复 |
| `app:set-settings` | 设置页 → SW | 局部更新设置 |
| `tts:speak` | 任意 → SW | 朗读 |
| `app:state-changed` | SW → 全部 | 广播，界面自动刷新 |

**记账放在 `card:shown` 而不是"下发时"**：如果页面侧最终否决（正在输入/放视频），这一次不应算进配额。

### 4.5 依赖说明

**生产依赖：0 个。** 不使用任何框架、构建工具、CSS 预处理器或 npm 包。
`package.json` 的 `dependencies` 与 `devDependencies` 都是空的，它唯一的作用是声明 `"type": "module"`，让 `tools/validate.js` 能用 Node 直接加载 `src` 下的 ES Module 做自检。

## 五、可选扩展

### 已内置（本次实现）

- ✅ **生词本导入 / 导出**：JSON、CSV、TSV、两列清单；进度按单词关联，重复导入不重置。
- ✅ **自定义词库**：设置页增删词条；也可直接替换 `src/data/words.js`。
- ✅ **分类筛选**：9 个场景标签，只学近期用得上的那批。

### 明确不做的事

- ❌ 不做学习课程、不做等级考试、不做排行榜 —— 会把"顺手学"变成"又一个任务"
- ❌ 不做强制打卡、不做错过提醒 —— 碎片学习的价值在于无压力
- ❌ 不做账号体系、不做云端 —— 个人使用场景下，`chrome.storage` 已经够用且更隐私
- ❌ 不做任何埋点与统计上报
